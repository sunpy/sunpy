************************
What's New in sunpy 8.1?
************************

The SunPy Project is pleased to announce the 8.1 release of the ``sunpy`` core package.

On this page, you can read about some of the big changes in this release.

.. contents::
    :local:
    :depth: 1

``sunpy`` 8.1 also includes a large number of smaller improvements and bug fixes, which are described in the :ref:`changelog`.

``Map`` is now built on ``ndcube``
==================================

`~sunpy.map.GenericMap` now inherits from `ndcube.NDCube` rather than `astropy.nddata.NDData`.
This is a large change to `sunpy.map` in terms of design, but it has been executed in a way designed to have as little impact as possible on you.
Maps are created the same way, carry the same attributes, and are plotted the same way, so most of your code will need no changes at all.
The result is that a ``Map`` now shares a common interface with the rest of the ndcube ecosystem, and that methods previously implemented within sunpy are now inherited.

The primary motivation for the change is future work and improved maintainability that will benefit the `sunpy` project long term but, there are some immediate user facing benefits to this change.

Slicing
-------

Maps can be sliced directly, returning a new map whose metadata describes the sliced region:

.. code-block:: python

    >>> import sunpy.map
    >>> from sunpy.data.sample import AIA_171_IMAGE  # doctest: +SKIP
    >>> aia = sunpy.map.Map(AIA_171_IMAGE)  # doctest: +SKIP
    >>> aia[100:200, 300:400]  # doctest: +SKIP

Cropping
--------

Maps can now be cropped in world coordinates with `ndcube.NDCube.crop`. This complements the existing `~sunpy.map.GenericMap.submap` method.
Both methods return a rectangular block of pixels, but they interpret the supplied coordinates differently.

`~sunpy.map.GenericMap.submap` interprets two coordinates as opposite corners of a rectangle in world coordinates and returns the smallest pixel rectangle containing it.
`~ndcube.NDCube.crop` instead returns the smallest pixel rectangle containing the supplied coordinates. It accepts any number of coordinates.

When the pixel and world coordinate grids are aligned, both methods return the same result.
When the map is rotated, they can return different regions. For example:

.. code-block:: python

    >>> from sunpy.data.sample import SWAP_LEVEL1_IMAGE  # doctest: +SKIP
    >>> rotated = sunpy.map.Map(SWAP_LEVEL1_IMAGE).rotate(30 * u.deg)  # doctest: +SKIP
    >>> bottom_left = SkyCoord(-900 * u.arcsec, -900 * u.arcsec, frame=rotated.coordinate_frame)  # doctest: +SKIP
    >>> top_right = SkyCoord(0 * u.arcsec, -200 * u.arcsec, frame=rotated.coordinate_frame)  # doctest: +SKIP

    >>> rotated.crop(bottom_left, top_right).data.shape  # doctest: +SKIP
    (335, 137)
    >>> rotated.submap(bottom_left, top_right=top_right).data.shape  # doctest: +SKIP
    (335, 358)

You can also use `~ndcube.NDCube.crop_by_values` with plain `~astropy.units.Quantity` values instead of coordinate objects.

See :ref:`sunpy-topic-guide-submap-vs-crop` for further explanation, and :ref:`sphx_glr_generated_gallery_map_cropping_a_map.py` for an example.

Unit conversion
---------------

The data of a map can now be converted easily to a different unit with `~ndcube.NDCube.to`, which scales the data values and records the new unit.
For example you could convert a magnetogram from Gauss to Tesla, or an AIA image from DN to kDN:

.. code-block:: python

    >>> import astropy.units as u
    >>> hmi_map.unit  # doctest: +SKIP
    Unit("Mx / cm2")
    >>> hmi_map.to(u.T).unit  # doctest: +SKIP
    Unit("T")


Metadata Changes
----------------

In general, operations that build a new map now carry more of the original Map with them.
`~sunpy.map.GenericMap.submap` keeps the uncertainty of its parent, and all map arithmetic (e.g. multiply) keeps the parent's mask and propagates its uncertainty.

The rest of the `ndcube.NDCube` API comes along too, including `~ndcube.NDCube.rebin`, ``fill_masked`` and `~ndcube.NDCube.axis_world_coords`.

Behaviour Changes
-----------------

The impact on users was minimal, but a few behaviours are different:

* `~sunpy.map.GenericMap.submap` now raises a `ValueError` for a bounding box that lies entirely outside the map, where it previously returned an empty map.
  Similarly, a rectangle with no area now returns the single pixel whose edge it shares, following the same rules as `ndcube.NDCube.crop`.
* Instantiating a map class directly now needs the NDCube style signature, i.e. ``MyMap(data, meta=header)`` rather than ``MyMap(data, header)``.
  We still *strongly* recommend using the ``Map`` factory instead of instantiating map classes via their constructor directly.

Several attributes are deprecated in favour of their ndcube or numpy equivalents, and may be removed in a future release:

* ``GenericMap.dimensions`` in favour of `~sunpy.map.GenericMap.shape`, noting that ``shape`` is in (row, column) order and a plain tuple, whereas ``dimensions`` was in (x, y) order and in pixel units, so indices need swapping when moving across.
* ``GenericMap.dtype``, ``ndim``, ``min``, ``max``, ``mean`` and ``std`` in favour of working with ``numpy`` operators on ``GenericMap.data`` directly.
* ``GenericMap.pixel_to_world`` and ``GenericMap.world_to_pixel`` in favour of the equivalent methods on ``GenericMap.wcs``.
  Note that these do not take or return pixel units.
